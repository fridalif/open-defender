# Open Defender

![coverage](https://img.shields.io/endpoint?url=https://gist.githubusercontent.com/fridalif/7fa26c09b8c489d79bbbaf8d53726345/raw/open-defender-coverage.json)

![open-defender.jpg](./open-defender.webp)

Комплексный инструмент с открытым исходным кодом для мониторинга и аудита безопасности Linux-серверов.

При необходимости агент может экспортировать события в **панель управления Light Defender** по зашифрованному WebSocket-соединению с оконечным шифрованием: все события всех серверов в одном месте вместо входа на каждый сервер. Эта возможность по умолчанию отключена и никогда не обязательна. Без раздела `exporter` в `config.yaml` агент работает полностью автономно и никуда не подключается; даже включённая, но недоступная панель не задерживает обнаружение угроз или блокировку. Протокол описан в [CLIENT.ru.md](./CLIENT.ru.md), страницы продукта доступны на [light-defender.ru/open-defender](https://light-defender.ru/open-defender).

## Установка

### Быстрая установка

Загрузите последний релиз для вашей архитектуры в `/usr/bin/open-defender`:

```sh
ARCH=$(uname -m)
case "$ARCH" in
  x86_64)        ARCH=amd64 ;;
  i386|i686)     ARCH=386 ;;
  aarch64|arm64) ARCH=arm64 ;;
  armv7l|armv6l) ARCH=arm32 ;;
  *) echo "Неизвестная архитектура: $ARCH"; exit 1 ;;
esac
sudo curl -L -o /usr/bin/open-defender \
  https://github.com/fridalif/open-defender/releases/latest/download/open-defender_$ARCH
sudo chmod +x /usr/bin/open-defender
```

Затем установите программу как службу systemd и запустите её:

```sh
sudo open-defender -i
```

Служба читает `/etc/open-defender/config.yaml`; проверьте его с `-t` и посмотрите активные мониторы с `-s` (см. [Использование](#использование) ниже). Последующие релизы устанавливаются командой `sudo open-defender -u`.

## Использование

```
Использование: open-defender [параметры]

Параметры:
  -i, --install    установить open-defender как службу systemd и запустить её
  -u, --update     обновить установленный бинарный файл из последнего релиза GitHub
  -t, --test       проверить текущую конфигурацию и завершить работу
  -s, --status     вывести включённые мониторы и завершить работу
  -r, --restart    перезапустить службу open-defender
  -h, --help       вывести это сообщение
```

Для `-t`, `-s` и `-h` права root не требуются; для остальных параметров требуются.

### Включённые мониторы (`-s`)

```sh
open-defender -s
```

```
/etc/open-defender/config.yaml

MONITOR           MODE     ENGINE   SOURCE                   TRIES
ssh_monitor       blocker  syslog   /var/log/auth.log        5 in 300s, ban 900s
database_monitor  logger   journal  postgresql               5 in 300s
resource_monitor  enabled  -        /var/log/open-defender/  cpu 60/90, ram 60/90

disabled: web_recon_monitor, web_brute_monitor
```

Монитор с `mode: disabled` никогда не запускается, поэтому он указан только внизу. `SOURCE` - файл журнала для движка `syslog` или модуль для движков `journal` и `docker`. Пределы монитора ресурсов выводятся как `warning/alert`; пределы со значением ноль отключены и не показываются. Как и при `-t`, конфигурация только читается и никогда не перезаписывается.

### Проверка конфигурации (`-t`)

Читает `/etc/open-defender/config.yaml`, сразу сообщает обо всех найденных проблемах и завершается с ненулевым статусом при наличии хотя бы одной. Конфигурация только читается и никогда не перезаписывается, поэтому команду безопасно запускать на работающей установке:

```sh
open-defender -t
```

Команда выявляет неизвестный `mode` или `engine`, `pattern`, который не компилируется или не содержит группу `(?P<ip>...)`, недоступный для чтения `log_path`, отсутствующий `unit_name`, нулевые `tries`, `window_seconds` или `ban_seconds`, предел `warning` выше `alert`, а также адрес в `ip_whitelist`, который не является адресом. Монитор с `disabled` пропускается, так как он никогда не запускается.

### Обновление (`-u`)

```sh
sudo open-defender -u
```

Последняя версия берётся из [version.txt](./version.txt) репозитория, а архитектура - из запущенного бинарного файла (`amd64`, `386`, `arm64`, `arm32`); оба значения предлагаются как варианты: пустая строка подтверждает предложение, введённое значение его заменяет. Если определить любое из них не удаётся, программа запросит его явно.

Затем релиз загружается из `https://github.com/fridalif/open-defender/releases/download/<version>/open-defender_<arch>`, служба останавливается, бинарный файл `/usr/bin/open-defender` заменяется, а затем служба снова запускается. Загрузка происходит до остановки службы; предыдущий бинарный файл сохраняется отдельно и восстанавливается, если новый не запустится.

### Перезапуск (`-r`)

```sh
sudo open-defender -r
```

## Сборка

Требуются Go 1.25+ и компилятор C (`gcc`), поскольку драйвер SQLite использует пакет cgo.

Соберите бинарный файл в `build/open-defender`:

```sh
make build
```

### Тесты

```sh
make test          # запустить все тесты
make test-verbose  # то же, с выводом по каждому тесту
make test-race     # запустить тесты с детектором гонок
make cover         # запустить тесты и вывести отчёт о покрытии по функциям
make cover-html    # то же, затем открыть отчёт о покрытии в браузере
make vet           # запустить go vet
make check         # go vet + тесты
make clean         # удалить артефакты сборки и очистить кэш тестов
```
